# 02 · AKKI-Website

> Meta-Projekt des AKKI Hackathon 2026.

**Idee:** Während des Hackathons entsteht ein eigener Webauftritt für den Arbeitskreis KI (AKKI) der AG Digitalisierung.

## Warum

Die Website macht den Arbeitskreis sichtbar und zeigt, was ein Team in zwei Tagen mit KI-Unterstützung bauen kann.

## Was am Ende stehen soll

- Ein Grundgerüst mit Startseite und klarer Seitenstruktur
- Mindestens zwei inhaltliche Unterseiten, zum Beispiel Projekte und Kontakt
- Eine echte, teilbare Live-URL

**Erfolgskriterium:** Die Website ist unter einer echten URL erreichbar.

## So startet ihr

1. Öffnet das [Ausgangs-Repository](https://github.com/akkidgou-opensource/02-akki-website) und meldet euch bei GitHub an.
2. Erstellt über **Fork** eure eigene Team-Kopie des Repositories. Eine Person verwaltet diese Kopie und lädt die anderen Teammitglieder als Mitarbeitende ein.
3. Arbeitet mit Claude Code im geklonten Team-Fork oder wählt den Team-Fork in ChatGPT mit Codex aus. Wie ihr euer eigenes GitHub-Konto verbindet, steht in der Anleitung unten.
4. Öffnet `SPICKZETTEL.md` und beginnt mit Block 1.
5. Die Schritt-für-Schritt-Anleitung steht in [GITHUB_ANLEITUNG.md](./GITHUB_ANLEITUNG.md).

## Zusammenarbeit im Team

Verteilt vor dem Bauen die Aufgaben und benennt pro Datei eine zuständige Person. Für jede unabhängig prüfbare Änderung wird ein eigener Branch erstellt und auf GitHub im Browser ein Pull Request geöffnet. So kann das Team Änderungen ansehen, Rückfragen stellen und sie erst danach in `main` übernehmen.

## Was in diesem Repo liegt

| Datei | Wofür |
|---|---|
| `SPICKZETTEL.md` | Umsetzungsplan für acht Stunden, Block für Block |
| `CLAUDE.md`, `AGENTS.md` | Gemeinsame Regeln für Coding-Agenten |
| `GITHUB_ANLEITUNG.md` | Fork, Teamarbeit und Pull Requests ohne Git-Vorkenntnisse |
| `daten/QUELLEN.md` | Welche Inhalte ihr braucht und woher sie kommen |
| `daten/hackathon-website/` | Die bestehende Hackathon-Seite als Vorlage |

## Stolpersteine

- Plant nicht zu viele Seiten.
- Stellt die Website früh online, nicht erst am letzten Nachmittag.
- Impressum und Datenschutzerklärung sind nötig, sobald die Website öffentlich ist.
- Verwendet niemals echte Patientendaten.

## Für Erfahrene

- Eine Projektseite, die die anderen Hackathon-Repositories automatisch auflistet
- Zweisprachige Inhalte (Deutsch und Englisch)
- Barrierefreiheit prüfen: Kontrast, Tastaturbedienung und Alternativtexte
